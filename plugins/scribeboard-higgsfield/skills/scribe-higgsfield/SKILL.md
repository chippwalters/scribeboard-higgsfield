# /scribe-higgsfield (plugin)

Everything not said here works exactly as in `${CLAUDE_PLUGIN_ROOT}/references/RENDER-SCRIBE.md` (read its **Roles**, **Stage 1**, **Stage 2**, **Stage 4** sections once before starting): the writer, the voice review, Gate 0, the script, the review loop, the board, Gate 2, the video and Gate 3. This file only changes **who makes pictures and audio** and **how**.

## Before anything

`${CLAUDE_PLUGIN_ROOT}` is this plugin's folder (Claude Code fills it in here; in the reference files it means the same folder). Commands below use `$S` = `${CLAUDE_PLUGIN_ROOT}/scripts` and `$PY` = the Python this machine's settings name: run `python "${CLAUDE_PLUGIN_ROOT}/scripts/settings.py" python` once and use what it prints.

0. **Setup.** `python "$S/install.py" check` must print `CHECK_JSON` with `"ok": true`. If `python` does not run, or `ok` is false, follow the setup wizard `${CLAUDE_PLUGIN_ROOT}/skills/setup/SKILL.md` first (it asks the user before installing anything), then come back here.
1. **Prerequisites.** `$PY $S/render_scenes.py doctor --style rsa_animate` must print `images.engine = 'higgsfield'`, the setup catalogs line and `all prerequisites present`; `$PY $S/narrate.py doctor` must end `"ok": true, "engine": "higgsfield"`; `$PY $S/runsetup.py catalog` must print `CATALOG_JSON` with `"required": true`. A missing machine path (Python, the speech-check venv `asr.whisper_python`, Chrome) belongs in the per-user settings file the doctor names (`%LOCALAPPDATA%\scribe-higgsfield\settings.json` on Windows), never in the plugin folder.
2. **Higgsfield.** Call `mcp__higgsfield__balance`. It must answer with credits; otherwise STOP and ask the user to sign in (`/mcp`). Note the balance: the run report compares it at the end.
3. **A new video:** `$PY $S/scribe.py new` opens the operating system's file dialog (starting in settings `runs_home`), and the user picks their story file (.md or .txt). The command waits until the user answers: run it in the background (or with a 10-minute timeout), never with a short timeout that would close the dialog under them. **Every file of the video goes into the story's own folder: that folder is the run (`RUN`).** The command prints it and the first step, the start page (Gate 0), which shows the story file and the folder. If the user cancels, run it again when they are ready. Where no dialog can open (no screen), it says so; then the story's full path goes to `scribe.py new --story FILE`. Never pick the story, move it or copy it yourself. To continue an existing video, use its folder.
4. **The credit guard.** This plugin's hooks (`hooks/hooks.json`, `scripts/hf_guard.py`) watch every Higgsfield generate call: they book each quote, mark each paid call `submitting` and record its job, and deny a paid call that matches no request the scripts printed (while a run is under way). A denial is never worked around.

Then follow `$PY $S/scribe.py status --run RUN`: it names the one next step every time, Higgsfield steps included. Run it after every step; never pick stages by hand.

## Gate 0 (start) and Gate 1 (script & setup): the user's choices, enforced by the scripts

Never choose any of these for the user, never ask them in chat, and never write `start.json`, `source.md` or `setup.json` yourself. The story comes from the user's file dialog, never from a file you put there.

- **Writer pass 0, the characters** (the first thing `scribe.py status` routes, stage `cast-find`): a fresh writer sub-agent reads the story file and writes `RUN/story_cast.json` (`{"written_by", "characters": [{"id", "name", "look"}]}`, at most 3; SCRIPT-WRITER.md "Pass 0"), then runs `runsetup.py cast-check`, which refuses a bad list and stamps a good one with the story's checksum. `gate5.py build` refuses without it.
- **Gate 0, the start page** (`gate5.py build`): it shows the story file and the video's folder, then asks **your words** (keep exactly, or rewrite as narration), **narrator voice** (56 voices with samples), the video's **title** (one line, preset from the story's heading; the narration's title and the title card), the **drawing style** (sample pictures), the **colours** (palette cards), the **image model** (Nano Banana 2.1, the default, or GPT Image 2.5; catalog `image-models/higgsfield.json`; it draws every scene, title and sheet of the video), **each character** pass 0 found (a character sheet drawn from the description, a sheet drawn from 1-3 image files plus the consent box, or **no sheet**: sheets are optional, and a character without one is described in each scene's prompt, with no reference, no sheet job and no sheet question on Gate 1) and the **credit budget** (a guide by length, for each model). `gate5.py apply` refuses invalid answers (never guess them). A valid answer writes `RUN/source.md` (the run's copy of the story) and `RUN/start.json` (version 3). Nothing is written, spoken or paid for before it, and the start does not change afterwards: a new story, voice, title, look, model or cast is a new video in its own folder.
- **Writer pass 1** writes `narration.json` from `RUN/source.md` with its **`title` exactly the start page's title** and **`characters` copied exactly from `start.json`'s cast** (`voice.py validate-narration` refuses any difference). With **keep my words** it only splits the script into paragraphs and sentences, and `voice.py validate-narration` checks the words one by one; there is no voice review. With **rewrite** it follows the profile `scribe.py status` names (the neutral `profiles/narrator.md`), and a voice reviewer checks it.
- **The narration is recorded next**, in the start page's voice, through the Higgsfield handoff below (`narrate.py tts-plan` / `tts-ingest` / `run`). Narration jobs need only the start page; the budget is the start page's.
- **Then the character sheets** (characters with a sheet only): drawn in the start page's style, colours and model before Gate 1 (`runsetup.choices` reads the start record until `setup.json` exists; only sheet jobs may run that early, `runsetup.require_pictures`), each with its fresh sheet review (below). `scribe.py` routes them after the narration.
- **Gate 1, the setup page** (`gate0.py build`; its rail and title say Gate 1): each paragraph with its recorded sentences to play, what Gate 0 chose (shown, not asked), **each character sheet** with an approve / edit question (an edit needs a note; `scribe.py` then routes `characters.py prep --force --fix`, a fresh sheet review and the next Gate 1 round; no scene is drawn until the newest round approved every sheet as it is now) and the **credit budget** (now the exact estimate), its only question besides the approvals. `gate0.py apply` refuses invalid answers (never guess them). Only a round that approves the script with valid answers writes `RUN/setup.json` (the budget, plus a copy of the start's choices). A paragraph edit sends it back through the writer (and the voice review when rewriting); changed sentences are recorded again.
- From then on the budget comes **only** from `setup.json`, and the voice, title, model, style, palette and cast only from `start.json`. Every scene picture prep refuses without both (`hf.ledger_check`). A writer who adds, drops or rewords a character is refused at the narration step (`voice.py validate-narration`).
- **Writer pass 2** uses the start's style and exactly its cast, with no `reference`, `title_text` exactly the start page's title and each character's `desc` exactly its look (the sheets were drawn from it). `scribe.py` refuses anything else.
- `$PY $S/runsetup.py check --run RUN` shows whether the setup is complete and why not.

## Roles

- **You (the main conversation)** make **every Higgsfield call** yourself: you are the only one holding the credit ledger. Use the agent name `orchestrator` wherever a command asks for `--agent`.
- **Sub-agents** (Claude Code `Agent` tool, `general-purpose`, a fresh one per job, each with a unique name such as `scene-review-3a2`) do what must be independent: the **writer** (pass 0, 1 and 2), the **voice reviewer**, the **picture reviewer** (`references/REVIEW-AGENT.md` of render-scribe), the **title reviewer** (`references/TITLE-REVIEW.md`) and the **sheet reviewer** (below). A reviewer is never `orchestrator` and never the writer. Briefs are self-contained: paste the reference file's full path, the run folder, the scene number and the agent's name. Sub-agents never call Higgsfield tools.

## The Higgsfield handoff (same for every paid job)

Every prep command prints one `REQUEST_JSON {kind, ref, tool, arguments, credits, ...}` line.

1. **Quote.** Call the tool named in `tool` (`mcp__higgsfield__generate_image` or `mcp__higgsfield__generate_audio`) with `arguments` exactly as printed **plus** `"get_cost": true` inside `params`. Note `cost.credits`. Every item of a batch is quoted on its own (one `generate_audio` quote per narration item).
2. **Book the quote and mark the submit (write-ahead).** The plugin's credit guard (a hook) does this by itself: after a quote it adds a note `scribe-higgsfield credit guard: quote ... recorded for REF`, and right before a paid call it marks the request `submitting` (or denies the call with the reason: never work around a denial). **Without that note** (no plugin hooks: a repo session, Codex, omp) do it yourself: `$PY $S/hf.py quote --run RUN --ref REF --credits C` for each quote, then right before the paid call `$PY $S/hf.py submitting --run RUN --ref REF` (repeat `--ref` for a batch). It re-checks the budget with the exact quotes; a refusal means STOP (do not submit).
3. **Submit once.** Call the same tool with `arguments` exactly as printed (no `get_cost`). Never edit the prompt or the parameters: the request is matched to its booking by a hash of its exact params.
4. **Record at once** (before waiting): the matching `submitted` command with `--job <id> --quoted <credits>` (the guard's note after the call names each job; the script's own command must still run, it updates the job's state). If the call errored, timed out or you cannot tell whether a job was created, record `--unknown "<what happened>"` and **never resubmit**: check `mcp__higgsfield__transactions` / `mcp__higgsfield__show_generations`, then record the real job id, or `--failed "not created"` on the ingest command.
5. **Wait** with `mcp__higgsfield__jobs_wait` (up to 12 job ids, each with an `index`) until every job is terminal; follow `poll_after_seconds`.
6. **Ingest** the result URL with the matching ingest command (`--url <url>`; the URL must be that job's: Higgsfield result URLs end in the job id), or `--failed "<reason>"` for a job Higgsfield reports failed (it refunds those). An ingest that fails after download problems is retried with the same URL; the job is paid, never resubmit it.

**A status line that starts `reconcile REF` or `record REF`** means a submit of that request already started (the ledger marked it `submitting`, or holds its job): never submit it again. Find the job in the account and record it with its `submitted --job`, or close it with `--failed "not created"` when the account has no such job. A `submitting` line older than 15 minutes stops every new prep until it is reconciled.

Every prep command reserves its jobs' estimated price in `RUN/credits.json` as it prints them, so jobs prepared side by side count against the budget before they are submitted. A job you will not submit (the user declined its quote, a sentence was dropped) must be closed: a narration take with `$PY $S/hf.py release --run RUN --ref <its ref>`; a picture with its own ingest command and `--failed "not submitted"` (that closes the attempt too). Always pass `--quoted` to `submitted` (without it the reserved estimate stands in). A prep command refuses when the run's spent and reserved credits plus the next job would pass the budget the user set on the setup page (`RUN/setup.json` `budget.cap`). Then STOP and ask the user; only with their answer, `$PY $S/hf.py cap --run RUN --set N` raises it (it updates `setup.json`). `$PY $S/hf.py status --run RUN` shows the ledger.

| Job | prep | submitted | ingest |
|---|---|---|---|
| Scene picture | `render_scenes.py render-prep --out RUN/scenes --scene N --agent orchestrator` | `render_scenes.py render-submitted --out RUN/scenes --scene N --attempt K --job ID --quoted C` | `render_scenes.py render-ingest --out RUN/scenes --scene N --attempt K --url URL` |
| Title card | `title.py prep --run RUN --agent orchestrator` | `title.py submitted --run RUN --attempt K --job ID --quoted C` | `title.py ingest --run RUN --attempt K --url URL` |
| Character sheet | `characters.py prep --run RUN --id ID --style STYLE` | `characters.py submitted --run RUN --id ID --job ID --quoted C` | `characters.py ingest --run RUN --id ID --url URL` |
| Narration | `narrate.py tts-plan --run RUN` (one item per sentence) | `narrate.py tts-ingest --run RUN --results FILE` with `[{"id", "job_id", "quoted"}]` | `narrate.py tts-ingest --run RUN --results FILE` with `[{"id", "job_id", "url"}]` (or `"failed"` in place of `"url"`; always give the line's `job_id`, so an old take's line never touches the new take) |

**Narration.** `tts-plan` prints `PLAN_JSON` with `items` (each `{id, take, ref, tool, arguments}`). Quote the first item, then submit all items; `mcp__higgsfield__generate_audio_batch` takes up to 12 requests at once (its requests are the items' `arguments.params`, `count` 1). Write the job ids to a file and run `tts-ingest` with it **before** waiting; after `jobs_wait`, write the URLs and run `tts-ingest` again. It downloads, checks every take and reports `passed` / `rejected`. Run `tts-plan` again for rejected or refunded sentences (up to 3 takes each); when nothing is left, `scribe.py status` routes `narrate.py run`, which builds the track.

**How a word is said.** When the user says a word is mispronounced, never guess one spelling. Seed Audio has no phoneme or SSML control, so the spelling is the only lever, and hyphens between syllables make the voice read each piece as its own slow word (`mee-dee-OH-ker` took 1.74 s where the word takes about 0.45 s). Run `narrate.py try-plan --run RUN --id <sentence> --word <word> --say <spelling> ...` (2-6 spellings without hyphens between syllables), quote one, submit them as a batch, and record each at once with `narrate.py try-submitted --run RUN --id .. --word .. --say .. --job .. --quoted ..`. After `jobs_wait`, download them to `RUN/narration/_tries/<id>/<spelling>.wav` and show them on an html-questions page (one audio player per option, plus the current take). Put the user's pick in `RUN/pronunciations.json` (`{"<word>": "<spelling>"}`), then `narrate.py try-adopt --run RUN --id .. --say <spelling> --url <its result url>`: the take the user heard becomes the sentence's take after the usual checks, with no new job. Then follow `scribe.py status` (track, scene timing, video, a new Gate 3 round).

What the take checks catch (all in `narrate.py`, all automatic; never pass a take by hand, never edit its audio):
- **Cut off at the end.** Seed Audio sometimes stops mid-sound (about 9 of 23 takes in the 2026-11-10 test). A complete take ends in digital silence; one whose last 50 ms are -50 dBFS or louder is rejected, and the next take of that sentence is asked for with a throwaway word after it (`<sentence> ... Okay.`, item `"padded": true`; submit its `arguments` unchanged). The pipeline cuts the take at its last pause, so the word absorbs the cut, and a padded take must then match its sentence exactly. When the voice leaves out the throwaway word (the cut then loses the sentence's end), the uncut take is checked as an ordinary take. A sentence cut off on all 3 takes gets one padded take more. After a fix to these checks, `narrate.py recheck --run RUN` judges the rejected takes again from their raw files, for free.
- **A lone click or breath** before the first word (Seed Audio adds one, then up to 0.85 s of silence): dropped, and both ends of every take are faded.
- **A word the voice keeps getting wrong** ("URL" came back "URL slash"): when `tts-plan` stops with "failed the take checks 3 times", add the word to `RUN/pronunciations.json` (`{"URL": {"say": "U-R-L", "heard": ["URL"]}}`); the sentence starts its takes over. Say so in your report: it changes how the word is spoken.
- After a change to these checks, `narrate.py retrim --run RUN` re-checks the run's takes from Higgsfield's raw files for free and marks failures for a retake (each keeps its old audio until a new take passes); then `tts-plan` as usual.

**Scenes.** Scene 1 goes alone first: it is the style reference (its job id is attached to every later scene and to the title). After it passes its review, **the user approves it on the style page** (`gate6.py build`, routed by `scribe.py status`; an edit reopens scene 1 with the note). Until then `render-prep` refuses every other scene and `title.py prep` the title. Never just open a picture in the photo viewer for approval: approvals are pages. After the approval, prep every renderable scene, quote and submit them, record each, wait for them together, ingest each, then dispatch one fresh picture reviewer per scene in parallel (`review-prep`, checklist, `verdict`, exactly as in render-scribe's Stage 2). `render_scenes.py status --out RUN/scenes` names each scene's next step (`render attempt N`, `submit attempt K`, `wait for job ... and ingest`, `review attempt K`, `reconcile ...`).

**Character sheets** (optional: only for the characters the start page gave a sheet, `runsetup.sheet_ids`; `characters.py status` lists only those, and `prep` / `upload` refuse the others; before Gate 1). A character drawn from photos (the start page's photo paths) needs them uploaded first:
1. `characters.py upload --run RUN --id ID` prints the `mcp__higgsfield__media_upload` arguments. Call the tool, save its **raw JSON result** to a file, then `characters.py upload --run RUN --id ID --response FILE` sends the photos (curl) and prints the `mcp__higgsfield__media_confirm` arguments: call it.
2. Before uploading, the user must have confirmed they have the person's consent (the start page's consent box; the scripts refuse photos without it).
3. Then `prep` / quote / submit / `submitted` / `jobs_wait` / `ingest` as in the table.
4. **Sheet review:** a fresh sub-agent opens `RUN/characters/<id>_sheet.png` (and the photos, if any) and checks: exactly six separate figures (three full-body views: front, three-quarter, side; three head-and-shoulders expressions: smiling, surprised, thoughtful, one each), **in any clear arrangement** (the prompt asks for two rows of three, but image models often lay them out otherwise; every scene attaches the whole sheet, so the arrangement does not matter: user decision 2026-11-11); **no lettering at all** except text the character always wears (a cap logo); one consistent character (face, hair, glasses, clothing); it matches the photos or the description, adding nothing they do not show (no glasses on a face without them); plain white background, no frames or panels; drawn in the run's style and colours only (skin and mouths left unfilled when the palette has no such colour). It records `characters.py review --run RUN --id ID --reviewer <its name> --pass`, or `--fail "<what the next sheet must change>"`; a fail goes back to `prep --force` (the note becomes the fix). After three sheets in a row fail their review, the third is flagged and goes to Gate 1 as it is, for the user to approve or edit (no fourth automatic attempt); a Gate 1 edit (`prep --force --fix`) starts a new count.

**Title card.** After every scene passed: `title.py build`, then the handoff (`prep`, quote, submit, `submitted`, wait, `ingest`); `ingest` runs the automatic checks; then a fresh title reviewer (`TITLE-REVIEW.md`, `title.py review-prep` / `verdict`).

## Gates, board, video

`scribe.py status` routes every page in order: Start (`gate5`), Gate 1 · Script & setup (`gate0`), Style · Scene 1 (`gate6`), Gate 2 · Images (`gate1`), Gate 3 · Video (`gate3`). There is no board page and no cast page: the sheets are approved on Gate 1, and after Gate 2 the board is built (`stitch.py board`) and the video rendered (`stitch.py build`) straight away; Gate 3 shows the finished video and the board image together, then one clip per scene cut on the narration so every sentence is whole (user decisions 2026-11-11). Each scene's answer says what kind of edit it asks for (camera/timing, narration, picture), and `scribe.py status` routes each: picture edits reopen their scenes (new attempts, reviews and Gate 2), narration edits go to "How a word is said" or the writer, camera edits to module.json and a re-render. Gate 3 marks any sentence recorded again since Gate 1 approved it. Each is an html-questions page opened in Chrome; the user clicks Copy answers and pastes the JSON; you write it to the page's `expectedAnswers` path and run `apply`. Image edits that change a picture start a new round (`render_scenes.py reopen`), whose next attempt goes through the handoff again.

- **An answer missing from the pasted JSON** (`apply` says "required question is unanswered"): never fill it in yourself. Ask the user to answer it on the page, or to say it in chat; only an answer they gave in chat may be added, with a `note` saying so and a fresh `savedAt`.
- **Scene excerpts** (`videos/Scene-NN.mp4`): `stitch.py build` holds each excerpt's last frame, silent, until at least 0.8 s after its last word (the next scene's camera move starts right after it in the full video). Narration that changes after the video was built (a retake, `retrim`) only needs `narrate.py run`, `render_scenes.py sync` and `stitch.py build` again, as `scribe.py status` routes it; the pictures and their approvals stand.

## At the end

Report: the final video path, the per-scene table, `$PY $S/hf.py status --run RUN` (quoted spend) and `mcp__higgsfield__balance` now versus at the start (the true spend). Every picture is stamped with its Higgsfield job id; `RUN/credits.json` lists every job.
